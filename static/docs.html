Documentation

Use the awsum CLI, plus the design documents that describe the language and its compiler.

Use

awsum build

Compile your program for a target picked with -t. With -o OUT the result goes to a file; omit it for stdout. 

# Compile to LLVM IR
awsum build --program-type cli -t llvm -o out.ll          src/Main.aww
# Assemble to native binary with clang, then run
clang out.ll -o program && ./program "world"

# Compile to JVM bytecode
awsum build --program-type cli -t jvm  -o AwsumMain.class src/Main.aww
# Run with java (the -D flags pin I/O charsets to UTF-8 so non-ASCII argv survives the JVM startup decode on hosts whose default isn't UTF-8 — Windows in particular)
java -Dsun.jnu.encoding=UTF-8 -Dfile.encoding=UTF-8 AwsumMain "world"

# Compile to CLR assembly
awsum build --program-type cli -t clr  -o AwsumMain.dll   src/Main.aww
# Run with dotnet
dotnet AwsumMain.dll "world"

# Compile to WebAssembly module
awsum build --program-type cli -t wasm -o out.wasm        src/Main.aww
# Run with wasmtime
wasmtime out.wasm "world"

# Compile to JavaScript
awsum build --program-type cli -t js   -o out.js          src/Main.aww
# Run with Node.js
node out.js "world"

awsum run

Compile to a temporary location and execute with the matching system runtime in one step — useful for trying things out without leaving build artifacts on disk. Pick the target with -t. Input passed via --input or --stdin reaches main directly. 

# Run with inline input
awsum run --program-type cli -t llvm --input "world" src/Main.aww

# Run with stdin
echo "world" | awsum run --program-type cli -t llvm --stdin src/Main.aww

awsum check

Check the program for errors and warnings, without producing any artifact. The fast feedback loop during development. 

# Human-readable terminal output
awsum check --program-type cli src/Main.aww

# JSON output for editor integrations
awsum check --program-type cli --json src/Main.aww

# Strict mode — escalate warnings to non-zero exit code (for CI)
awsum check --program-type cli --strict src/Main.aww

awsum format

Format the source file. The implementation is "parse, then render". 

# Format and rewrite the file in place
awsum format -i src/Main.aww

# Print formatted source to stdout
awsum format src/Main.aww

Additional inspection commands — ast, core, asm, symbols — see awsum --help.

Further reading

Design documents and the bundled prelude. They live in the compiler repo on GitHub — single source of truth, kept in lockstep with the released compiler.

Design documents

  • principles.md — what the language guarantees and how the compiler resolves trade-offs.
  • type-system.md — user-facing type-system reference with examples that compile and examples that get rejected.
  • pipeline.md — phase-by-phase walkthrough of awsum build: parse → typecheck → lower → Core-to-Core → backend.
  • recursion.md — Scc → Cps → Tco passes that turn any recursion shape into a stack-safe loop on every backend, with no user annotation.
  • memory-management.md — how heap allocations are reclaimed: host GC on JVM/CLR/JS, compiler-emitted reference counting on LLVM/WASM, with no user annotation.
  • prelude.md — how stdlib/Prelude.aww coexists with per-target compiler implementations via BuiltIn.foo.
  • targets.md — per-backend implementation details (LLVM IR, JVM bytecode, CIL, WAT, JS).
  • platform-version-policy.md — minimum-version rule per backend (latest LTS for server / browser; oldest manufacturer-supported for mobile).
  • compatibility.md — supported targets and host-OS / architecture matrix exercised in CI.
  • testing.md — snapshot vs property-test layers and the post-feature workflow.
  • grammar.ebnf — formal surface grammar.
  • roadmap.md — short, public-facing roadmap.

Bundled prelude

  • stdlib/Prelude.aww — every program gets Maybe, Either, Bool, bindEither, showInt32, and friends without an import. Read it to know what's available out-of-the-box.
