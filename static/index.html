Awsum

GitHub

A functional language where computation results are guaranteed equivalent across all compilation targets.

Why Awsum

Equivalent results everywhere. When a program compiles for LLVM and JVM, both produce identical output — not by convention, but by design. Unlike Haskell/GHC vs GHCJS or PureScript's backends, Awsum treats cross-target equivalence as a compiler invariant, not a best-effort goal. The test suite runs 58 programs end-to-end on all six backends and asserts byte-identical stdout on every commit.

Stack-safe recursion by default. Write the recursion that expresses the algorithm — self-recursive, mutual, non-tail, whatever — and the compiler turns it into a loop without a stack frame per call on any backend, including JVM and JS where native cross-method tail calls do not exist. No tailRecM ceremony à la PureScript, no manual CPS transforms. Stress tests run at depths up to 1 000 000 on every target.

Honest arithmetic. Arithmetic that can over- or underflow returns Either, not a silently-wrapped result. Today the prelude exposes predInt32 / succInt32 : Int32 -> Either {Underflow,Overflow}Error Int32 and the same shape for UInt8. Every operation that can fail says so in its type; the programmer decides how to handle it, and the compiler cannot "just return zero" or NaN.

Platform effects are compile-time gated. Effects are tied to the compilation target. Today the CLI program type exposes IO.Stdout.print, and a program using it cannot be compiled for a target that doesn't support it. "Not supported" is a compile error, never a runtime surprise.

Targets

Target Runtime Minimum version
LLVM Native binary via Clang LLVM 15+ (opaque pointers)
JVM Java bytecode (generated directly, no Jasmin/javac) Java 7+ (CONSTANT_MethodHandle)
CLR .NET DLL (generated directly, no ilasm/csc) .NET 9+
WASM WebAssembly via WASI wasmtime (WASI preview 1)
JS Node.js, browser (planned) Node.js 22+ (LTS)
Lua Lua interpreter Lua 5.1+

Every target produces identical stdout for the same input. See Target Implementation Details for how each backend works under the hood.

Editor support

VSCode

Install the Awsum extension to enable:

  • Syntax highlighting (including integer literals)
  • Formatting (on save or on demand)
  • Inline error diagnostics (red squigglies) and warnings (yellow squigglies, theme-aware)
  • Quick fixes (lightbulb) for unused bindings
  • Outline view, breadcrumbs, and in-file symbol navigation (Ctrl+Shift+O / @)
  • Workspace-wide symbol search (Ctrl+T)

Recommended settings:

{
  // settings.json
  "[awsum]": {
    "editor.formatOnSave": true,
    "editor.defaultFormatter": "awsum-lang.awsum-vscode"
  }
}

Installation

Compiler

# Install Stack (Haskell build tool)
ghcup install stack

# Build and install the compiler
stack build
stack install

# Make sure ~/.local/bin is in PATH

Target runtimes

Install only the runtimes for the targets you need:

# LLVM — native binary compiler (opaque pointer support requires 15+)
brew install llvm@15

# JVM — Java runtime (Java 7+)
# https://get-coursier.io/

# CLR — .NET runtime (.NET 9+)
brew install dotnet

# WASM — WebAssembly runtime with WASI support
brew install wasmtime

# JS — Node.js interpreter
# https://nodejs.org/

# Lua — Lua interpreter
brew install lua

Usage

  • awsum build FILE --program-type cli [-t llvm|jvm|clr|wasm|js|lua] [-o OUT] — compile to target and write to file (or stdout). For JVM, CLR, and WASM, outputs binary (.class / .dll / .wasm).
  • awsum run FILE --program-type cli [-t llvm|jvm|clr|wasm|js|lua] [--input TEXT | --stdin] — compile to a temp file and execute with the system runtime, passing input to main.
  • awsum check FILE --program-type cli [--json] [--strict] — parse, typecheck, and run stack-safety verification. Prints OK, warnings, or an error. With --json, outputs a structured array of diagnostics with source spans and quick-fix edits. With --strict, any warning causes a non-zero exit code (CI-friendly).
  • awsum format FILE [-i|--in-place] — render . parse with stable formatting. Preserves comments (including trailing inline), keeps a blank line between top-level blocks, and ends the file with a trailing newline.
  • awsum ast FILE — pretty-print the surface AST (debugging).
  • awsum core FILE --program-type cli — print elaborated and lowered Core IR (debugging).
  • awsum asm FILE --program-type cli [-t jvm|clr|wasm] — print target assembly text: Jasmin-like for JVM, CIL for CLR, WAT for WASM (debugging).
  • awsum symbols FILE [--json] — list top-level declarations (outline). With --json, emits an LSP-style DocumentSymbol array.
  • awsum --version — show version.

Examples:

awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t llvm --input "world"
awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t jvm  --input "world"
awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t clr  --input "world"
awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t wasm --input "world"
awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t js   --input "world"
awsum run test/sources/successful/hello/code/Main.aww --program-type cli -t lua  --input "world"

awsum build test/sources/successful/hello/code/Main.aww --program-type cli -t llvm -o out.ll  && clang out.ll -o out && ./out "world"
awsum build test/sources/successful/hello/code/Main.aww --program-type cli -t js   -o out.js  && node out.js "world"

awsum check  test/sources/successful/hello/code/Main.aww --program-type cli
awsum check  test/sources/successful/hello/code/Main.aww --program-type cli --json
awsum format test/sources/successful/hello/code/Main.aww -i
awsum ast    test/sources/successful/hello/code/Main.aww
awsum core   test/sources/successful/hello/code/Main.aww --program-type cli
awsum --version

Design principles

  1. Identical results on every target. The same program produces the same stdout whether compiled for LLVM, JVM, CLR, WASM, JS, or Lua — byte-for-byte, verified by the test suite on every commit. This is a compiler invariant, not a best-effort goal; the rest of the design hangs off it.
  2. Stack safety belongs to the compiler, not the user. Recursion — tail, non-tail, self, mutual — is normalised at Core level into a shape that runs in bounded stack on every backend, including JVM and JS where native cross-method tail calls do not exist. No manual CPS transforms, no tailRecM, no hand-unrolling. Write the recursion that expresses the algorithm; the compiler makes sure it doesn't fall over.
  3. Effects are platform-aware. The compiler tracks which effects each target supports. A program using Terminal won't compile for a browser target; a program using Window won't compile for CLI. "Not supported" is a compile error, never a runtime surprise.
  4. Errors are values. Arithmetic doesn't silently break. Division by zero, overflow, underflow, precision loss — all represented in the type system via Either. The programmer decides how to handle them; the compiler cannot "just return zero" or NaN.
  5. No invisible decisions. When something has to be chosen, the programmer chooses — not the compiler. No defaulting of integer literals to a type the compiler guessed (ambiguity is rejected with an explicit hint); no silent shadowing of an outer name by an inner one (shadowing is a compile error); no quiet reference to something the programmer marked as unused (_-prefixed bindings cannot be read). The rules are small; the shared root is that nothing meaningful is decided behind the reader's back.
  6. Priority order when trade-offs appear:
    1. Correctness — no runtime exceptions, no platform-behaviour differences, no surprising overflow / underflow / string corruption.
    2. Runtime performance — generated programs should be fast.
    3. Compilation speed — the compiler itself can be slower if it produces better output.
  7. The computer writes the compiler. Implementation details would be chosen by hand, but choosing by hand got us JavaScript. So the computer chooses. It knows.

What's implemented

Verified by the test suite on all six backends:

  • Cross-target equivalent stdout — compiler invariant
  • Stack-safe recursion (self / mutual / non-tail) via SCC merge + CPS + TCO
  • Sum types (parametric, empty / uninhabited), exhaustive pattern matching, polymorphic type variables, first-class constructors
  • Int32 and UInt8 integer types with compile-time range validation of literals
  • Prelude-visible types (Bool, Either a b, Maybe a, UnderflowError, OverflowError) and helpers ((++), not, and, or, show / pred / succ / eq on Int32 / UInt8)
  • Honest Either-based arithmetic for predInt32 / succInt32 / predUInt8 / succUInt8
  • Compile-time platform-effect gating (CLI program type)
  • Whole-program reachability tree-shake

For directions under consideration, see the roadmap.
